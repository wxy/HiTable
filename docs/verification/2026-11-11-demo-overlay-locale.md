# 演示页语言一致性与页脚修复

日期：2026-11-11；基线为 `a90374b5a9150dead6f8602d4ee84808a1e79254`（首次 v0.2.2）。用户授权通过 PR 修复、验证、审查后合入，并更新同版本发行附件；商店最终提审仍由用户操作。

## 原因与实现

- 演示页的翻译只更新 data-i18n 元素；active.js 在目录加载前初始化，算法名称及动态提示直接调用 Chrome 消息接口。因此页面指定 ro／zh_HK 后，浮层仍显示当前浏览器的简体中文。
- 页脚整段 p 带 data-i18n，textContent 更新删除了其中 Help 与 GitHub 的 a 元素，剩余的不完整前缀正是用户看到的文本。
- page-i18n 公开当前页面目录的 Promise，demo 先加载它，浮层等待后使用同一个 getMessage；所有算法、方向、手柄、尺寸、统计／异常／完整性提示及复制成功／失败消息统一调用该函数。未改写 Chrome API。普通网页不加载该目录，继续使用原生消息接口。
- 入口统一连字符／下划线 locale 表示，并沿用已有支持列表与未知语言回退英文规则；现有目录的占位符均为 $1$…$4$，替换时支持原调用中的字符串／数组参数，静态核对全部元数据。
- 页脚把翻译文本与两个导航链接拆开，保留真实 a 元素及其 href。帮助链接内部沿用解析后的语言。补齐七种目录中旧的英文演示说明、列类型和统计异常提示；示例表格的数据不改。
- 按用户最新指示，参数仍属内部预览／截图用途；没有新增用户帮助正文或设置说明，也没有改设置页实现。

## 修改前后的证据

系统 Chrome 实际 UI 为 zh-CN。修改前用真实扩展分别打开 locale=ro、zh_HK，各检查算法 SUM、复制提示和页脚链接，共 **6 项均按预期失败**：算法均为“求和”，复制提示均为“已复制选区：2 行 × 2 列”，页脚两个链接均丢失。同一输入修复后 6 项通过；最终归档 ZIP 的完整矩阵另计如下，不重复累计。

### 负向验证的限制

扩展源的单独权限覆盖被 Chrome 拒绝为 opaque origin；全局权限覆盖及失焦输入也未能可靠触发预期失败。因此复制错误通知改为上述受控 API 拒绝，只证明错误分支的本地化，不算真实系统权限失败验收。没有把这些工具限制报告为产品缺陷或通过。

## 复现

1. 将正式 ZIP 解压，用干净 profile 加载扩展。自动化临时安装 playwright@1.65.0，系统 Chrome headless，ignoreDefaultArgs=['--disable-extensions']，args=['--enable-unsafe-extension-debugging']。浏览器语言保持 zh-CN。
2. 按目录名访问内部 demo URL；等待 #HiTableStyle attached（说明共享目录已解析并启动浮层）。财务表从 DOM rows[1].cells[0] 中心拖至 rows[2].cells[2] 中心，8 步；菜单选择 MIN。每个文本与对应 _locales 的消息对照，模板值使用方向、算法、2、3。
3. 单次及快速双次 ⌘C 后读取 clipboard.readText，检查两类通知。清除选区后点击页脚 Help，等待真正的新标签页，核对 locale 查询及本地化标题。
4. 普通页通过临时 localhost 服务提供一个 lang=en 的 2×2 table，数字 10/20、30/40，td 为 1px border / 18px padding / 120px min-width，table margin=120px；注册 table pointerdown 计数。URL 带 locale=ro，通过真正工具栏 action 激活并拖选，再改源值、复制、停用及点击。
5. 负向复制场景仅在该临时页上定义 clipboard.writeText 的拒绝实现，检查 toast 后立即删除此属性恢复原生 API；不用于验证数值、剪贴板数据或真实权限。
