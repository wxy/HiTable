# 设计色板、页面背景选择与深色高亮验证

日期：2026-11-11。基线：`390d43a54ae6a5cd5444924af9fc66b8d2b8875d`，继续更新 PR #63，等待用户本地验收；不合并、不发布、不改版本。

## 最终设计

每套主题明确指定六个值：数据区浅色及文字、统计区主色及文字、深色高亮及文字。十套色板集中在 scripts/themes.js，配置页和浮层共用；自动模式只从这些主题中选择，不再临时计算整套颜色。绿色示例：

| 区域／状态 | 背景 | 文字 |
| --- | --- | --- |
| 普通数据格 | `#6bc78f` 浅绿 | `#10251b` |
| 普通统计带／算法角点 | `#27ae60` 绿色 | `#10251b` |
| 十字、对应统计格、当前算法角点及其统计带高亮 | `#16683b` 深绿 | `#ffffff` |

- 数据区和外围统计格的当前行列统一使用深色高亮，替换上一轮的内外深浅互换。
- 悬停四角时，当前角点与其对应统计带一起高亮，另一个角点保持主色；点击仍打开算法菜单。
- 灰显、异常脉冲、复制、手柄和工具栏启停机制保留。悬停不增添边框、outline 或改变格子尺寸。
- 菜单当前项的文字使用色板的深色；较亮主色只用于统计区背景，配套前景色已分别指定。

## 灰色页面与浅蓝行悬停的区别

演示页 body 的实际背景为 `linear-gradient(135deg, #f5f7fa 0%, #c3cfe2 100%)`，即用户看到的灰色渐变。`table.demo-table tr:hover td` 另有 `background:#f0f7ff`，这个浅蓝色只属于鼠标所在表格行。此前提到的蓝色来源指后者，不是把整页背景判成蓝色。

自动模式现在只读取 html/body 的背景并合成透明层，忽略表格、单元格和它们的容器底色。演示页的 RGB 渐变按颜色停靠点取代表色；它不是截图采样或逐像素还原。中性白／灰底选绿色，深底选青绿色，较有色相的浅底从既有色板选对应颜色。固定模式使用用户选定色板，不随页面背景改变。

本轮取代了此前根据表格背景生成 RGB、动态调整明暗及自动选择文字色的方案。历史报告中旧自动 RGB 值和背景对比目标只属于当时的实现；本轮验收为固定设计色板、状态层级及文字可读性，不声称每个页面底色都能与浮层达到统一对比度。

## 重复执行方法

独立系统临时目录安装 Playwright 1.65.0，按[既有 CDP 方法](2026-11-11-consistent-protected-selection.md)加载扩展和触发工具栏。执行入口形式为 `node "$HITABLE_THEME_TEST_DIR/tools/verify.cjs"`（28 项）、`node "$HITABLE_THEME_TEST_DIR/tools/menu.cjs"`（10 个主题菜单）。

- 自带财务表选区为源表 rows[1].cells[0] 到 rows[7].cells[8]，中心到中心拖动 8 步；等待 #HiTableStyle attached。配置页通过原生 boxColor radio 选择十个固定颜色。普通数据取浮层 rows[3].cells[4]，统计格取 rows[0].cells[4]，比较正常／悬停样式和所有 td DOMRect。
- 四角通过 `.HiTableAlgorithmButton[data-direction] span` 悬停，先移出再移入、等待 30ms，检查 edge-highlighted 数量、自身属性、其他角点和文字。四边路径取 `[0,4]`、`[8,4]`、`[3,0]`、`[3,10]`。非数值取 `[3,1]`。对比度由实际 sRGB 背景与前景按相对亮度计算；菜单 color-mix 先用浏览器 canvas 解析为 sRGB。
- 自动背景场景依次设置 body.style.background 为 #fff、#10171e、#fff0f5、#808080、#e0efff；表和其 section 分别设为上表列出的干扰色。每次 Esc 后重选取得新页面背景快照，验证主题主色对应既有预设，且三层背景均逐项匹配主题数据。
- localhost 页面使用白色 body、margin 120px、2×2 table（10,20 / 30,40），td 宽 120px、高 40px、边框 1px，tr:hover td 为 #f0f7ff。表注册 pointerdown 计数；通过 Extensions.triggerAction 激活／停用／再激活，真实鼠标拖选及点击，核对浮层和计数。临时 HTTP server 在测试结束关闭。
