# 选区 UI 反馈修复与演示页验证

日期：2026-11-11。基线：`ad4017dad466bf1162e29a768b27a8f70c15de6f`，同一 PR #63 的后续修复。用户要求继续保留 PR，不合并、不发布新版。

## 原因与改动

- 财务表 `demo-financial` 的原数据格高 **34px**，旧浮层为 **35.1875px**。浮层复制源 padding，但使用自身行高；表格单元格的 height 不能阻止内容将其撑高。原列宽缓存还使用会取整的 offsetWidth，造成累计横向误差。
- 浮层单元格取消布局边框和 padding，把 padding 放进绝对定位的内容容器；内容不再决定表格尺寸。网格改为单侧 1px 亮色内阴影，选区框及悬停统计格使用 1px 白线。内阴影、outline 和独立选区框不参与数据格布局。
- 列宽／行高缓存保留 getBoundingClientRect 的小数精度。演示页财务表全部 63 个数据格实测与源格宽高一致，最大差值均为 0px。
- 旧手柄只对原表几何做平移补偿。现在以浮层实际列宽、行高及数据区位置建立调整坐标，命中和预览使用同一个网格；向选区外扩展时沿用缓存尺寸和数据，不依赖当前源表布局。
- 原来按下后不移动、直接松手也会生成浮层。现在移动距离达到 4 CSS px 才开始选取，单击及轻微抖动不选取；仍可在一个格子内部拖动选择单格。激活期间表格事件归属不变，没有恢复网页点击处理器或增加第二套激活开关。

## 松手后浮层消失：尚未复现

用户进一步确认：没有修饰键或算法变更，拖选期间可见选区，松手后消失。

在原提交的独立临时扩展副本上，以 1280×900 viewport 对财务表和嵌套财报各执行 110 次双向拖选，未出现“拖动有选择标记、松手后没有浮层”，也未捕获页面／控制台错误。修复版在下面的 324 次财务表选择中同样未出现。已检查 pointerup → releasePointer → showOverlay → calculation，以及取消／失焦／丢失指针捕获路径；没有证据确认其中哪条路径触发用户现场问题。

**此项保持待确认，不能把未复现写成已修复。** 未增加吞异常、失败后伪装成功或忽略真实取消事件的分支。用户现场再次出现时，需要松手位置及当时控制台的 `HiTable [MouseUp]` 或其他错误，以区分生成／计算异常与实际取消事件。合入仍等待用户测试。

## 重复执行方法

在系统临时目录安装 Playwright 1.65.0，按[已有报告中的 CDP 启动方法](2026-11-11-consistent-protected-selection.md)启动系统 Chrome 并加载仓库，打开扩展的 `pages/demo.html`，等待 `#HiTableStyle` attached。使用默认配置；主 viewport 为 1500×1100，基线消失排查为 1280×900，窄屏为 390×800。

下面 r/c 是原表 rows/cells 的索引，含表头；DOMRect 坐标使用 viewport 坐标。每个独立场景先 Esc 清除旧选择，并把对应表 scrollIntoView 到 center。鼠标用 move → down → move（8 步）→ up；相同起止格时终点向右偏移 7px，以区别单击。

- 财务表选取 `[1,0]` 到 `[7,8]`；对原表 rows[1..7].cells[0..8] 与浮层 rows[1..7].cells[1..9] 的 getBoundingClientRect 宽高逐项比较。悬停浮层第三行第四列前后比较所有格子的 DOMRect，并读取 edge-highlighted 格的 computed outline。
- 四角测试初始选取 `[1,1]` 到 `[5,6]`。分别从 SE/NW/NE/SW 手柄中心拖到浮层数据区零起算 `[2,3]`、`[1,1]`、`[1,3]`、`[2,1]` 中心；预览在松手前读取，提交后逐格与期望原文比较。
- 重排测试在初始选取后修改源表 td.style.height、padding 和 textContent，再拖 SE 到可见数据格 `[2,3]`；不要刷新，否则会清除快照。扩展测试从原表 `[1,1]..[2,2]` 开始，按浮层首格与源首格的偏移映射到原表 `[4,5]` 的缓存位置。
- 财务横向区间生成：`r=1..7, start=0..8, end=start+1..8`，共 252 个区间；每次 Esc 后重选，比较数据原文。72 个点击／单格拖选使用 `r=0..7,c=0..8`。原提交的消失排查对两个表的所有叶 td/th 取中心，使用 `start=(i*17+3)%count,end=(i*29+7)%count,i=0..109`，比较松手前的选择标记和松手后的浮层数量。
- 其他表 ID 为 demo-sales、demo-schedule、demo-nested、demo-integrity、demo-regional、demo-cssgrid、demo-ariagrid。CSS Grid 不使用 demo-divgrid。复制用 Meta+C 并读取真实 navigator.clipboard，context 先授予 clipboard-read/write 权限。

当次执行命令形式：`node "$HITABLE_UI_TEST_DIR/tools/verify.cjs"`；诊断原提交使用独立临时运行副本及 `diagnose-release.cjs`。全部输入来自上面的正式演示页，额外修改仅是源表重排场景中的明确操作。测试工具、原提交临时副本、profile、日志、JSON 结果和截图不进入 Git；记录本报告后清理。
